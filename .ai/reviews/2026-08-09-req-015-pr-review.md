### Correctness / security (product)

| Severity | Location | Finding | Fix |
|----------|----------|---------|-----|
| **high** | `db::seed_discord_allowlist_from_config` + `upsert_discord_allowlist` ON CONFLICT | **Boot seed demotes UI-granted admins.** Every start upserts each `DISCORD_ALLOWLIST` id with `is_admin = DISCORD_ADMIN_IDS.contains(id)`. Confirmed in SQLite: row `111` with `is_admin=1` becomes `0` after seed with allowlist=`111`, admin_ids empty. Dashboard “Als Admin” is wiped on restart unless the id stays in `DISCORD_ADMIN_IDS`. | Seed must be **additive / promote-only**: insert if missing; on conflict update username only; set `is_admin=1` when env says admin; **never** force `is_admin=0` from env. Add regression test: UI promote → re-seed → still admin. |
| **high** | `handlers/allowlist.rs` `add_allowlist` → `upsert_discord_allowlist` | **Last-admin guard bypass.** Toggle/delete call `set_*` / `delete_*` which bail on last admin. Add path always writes `is_admin` from checkbox (unchecked → false) via upsert ON CONFLICT. Re-adding the sole admin without checkbox → **zero allowlist admins**. | On conflict: preserve `is_admin` unless explicitly promoting; demotions must go through `set_discord_allowlist_admin`. Test both. |
| **medium** | `auth/session.rs` `AuthUser` | Allowlist enforced **only** at OAuth callback. Removing an id (or emptying table) leaves existing Discord sessions valid for up to 7 days inactivity. Revoked user keeps tickets/gear/ingest; can still open `/admin/login` and elevate with `ADMIN_PASSWORD`. | Re-check `is_discord_allowlisted` in `AuthUser` (or middleware); clear `USER_ID_KEY` (+ optionally `ADMIN_KEY`) when not listed. System test: login → delete allowlist row → next authed request → `/login`. |
| **medium** | `pages::admin_login_submit` + `AuthUser` | Password elevation requires Discord session only — **not** current allowlist membership. Intentional vs REQ-015 wording, but combined with session non-revocation it is a durable backdoor after revoke. | Prefer: password elevate only if still allowlisted (or document as accepted residual risk). |
| **medium** | `set_discord_allowlist_admin` / `delete_discord_allowlist` | Last-admin check is TOCTOU (count then update), not a single transaction/`WHERE` constraint. Two concurrent demotes of two admins can both observe `count=2` and both succeed → zero admins. SQLite limits practicality; still a real race under HTMX double-submit / two admins. | Use a transaction; or `UPDATE … WHERE is_admin=1 AND (SELECT COUNT(*) …) > 1`; assert `rows_affected`. |
| **medium** | Deploy ops / empty allowlist | Compose defaults `DISCORD_ALLOWLIST` / `DISCORD_ADMIN_IDS` to empty. Fail-closed is correct, but a deploy that only sets `ADMIN_PASSWORD` **cannot** reach `/admin/login` (needs Discord session first) → **hard lockout** until env seed fixed + restart. | Document prominently in compose comments + `.env.example`; consider boot ERROR (not only WARN) when allowlist empty. |
| **medium** | `.env.example` / `deploy/app/.env.example` | Placeholder `YOUR_DISCORD_USER_ID` is seeded as a real row (non-numeric). Operator who forgets to replace gets a useless allowlist entry; all real Discord logins denied. Seed does not validate snowflake digits (handler add-path does). | Comment-only examples; validate `^[0-9]+$` in seed (skip + WARN invalid). |
| **low** | `handlers/allowlist.rs` error responses | Validation/DB errors return `<div id="allowlist-out">…` while form `hx-target="#allowlist-list"`. Error **replaces the table** with a lone feedback div; list disappears until full page reload. | Mirror success: render list + OOB `#allowlist-out`, or `hx-target`/`hx-swap` aligned with errors. |
| **low** | `toggle_allowlist_admin` | Button posts empty form → flip branch. `form.is_admin` explicit branch is dead from UI; API shape reuses `AddAllowlistForm` confusingly. | Dedicated empty body / `ToggleForm`; drop unused branch or document. |
| **low** | `allowlist.rs` last-admin errors | Matches `err.to_string().contains("last allowlist admin")` — brittle if `anyhow` context wording changes. | Typed error / `downcast` / stable error code. |
| **low** | `admin_logout` | Still public POST; only clears `ADMIN_KEY`. Fine functionally; no CSRF token (mitigated by `SameSite=Lax`). Discord allowlist admins: “Admin abmelden” clears password flag but **nav `is_admin` stays true** via allowlist — button looks like full admin logout but isn’t. | Copy: “Passwort-Admin beenden” or also no-op message when allowlist admin; optional. |
| **nit** | Path params on allowlist mutate routes | `discord_id` not re-validated as digits (add path validates). Env-seeded junk ids remain operable. | Shared `parse_snowflake` helper. |
| **nit** | `ROUTES-AND-DATA.md` | Allowlist routes labeled handler area `api`; code is `handlers/allowlist.rs`. | Fix table to `allowlist`. |
